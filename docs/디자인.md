작성일: 2026-09-26 · 상태: 레퍼런스 검토 및 웹 화면 시안 구현

이 문서는 [서비스 기획서](기획서.md)의 시험지·OMR·성적표를 구현하기 위한 시각 기준입니다. **흰 시험지, 명조 본문, 굵은 고딕 영역 제목, 가는 구획선**을 기본으로 합니다. 아래 HEX·크기·간격은 별도 표시가 없는 한 레퍼런스를 웹으로 옮기기 위해 정한 프로젝트 값이며, 평가원의 공식 디자인 규격을 의미하지 않습니다.

### 1.2 관찰과 적용 결정

| 레퍼런스에서 확인한 특징 | fe-mouigosa에 적용할 방식 |
| --- | --- |
| 문제지의 제목은 고딕, 긴 본문은 명조로 구별됨 | 영역 제목은 Noto Sans KR 800, 본문은 나눔명조 400 |
| 큰 영역 제목 아래 가로선과 2단 중앙선이 이어짐 | 헤더 아래 2px 선, 본문 중앙 1px 선 |
| 지문 상자와 문항 사이 여백으로 내용이 구분됨 | 필요한 지문·코드에만 사각 테두리, 문항 전체는 여백으로 구분 |
| 교시 표기는 작은 타원형 외곽선 안에 있음 | `제 1교시`에만 얇은 타원형 테두리 사용 |
| 국어 OMR은 녹색 구획과 분홍색 답란을 사용함 | OMR에 한해 짙은 녹색과 장밋빛 답란 적용, 선택한 답은 검정으로 채움 |
| 성적통지표는 영역을 열, 점수 지표를 행으로 배열함 | 영역별 점수·백분위·등급을 한 표에 정렬 |
| 문제지와 성적통지표에 성명·수험번호가 표시됨 | 시작 화면에서 성명을 받고 번호를 자동 발급해 문제지와 성적표에 동일하게 표기 |

확인한 문제지 PDF의 페이지 크기는 `842 × 1191pt`이며 `pdfinfo`에서 A3로 표시됩니다. **이 프로젝트는 사용자가 지정한 A4 비율 `210:297`을 유지**합니다. 원본 PDF의 판형과 프로젝트의 화면 규격을 구분합니다.

문제지 1쪽의 포함 글꼴 목록에서는 `신명-중명조`, `한양신명조`, `신명-태고딕` 등의 이름을 확인했습니다. 이 목록만으로 각 텍스트의 글꼴을 단정하지 않으며, 원본 폰트를 추출해 사용하지 않습니다. 아래 웹폰트는 인상이 유사하도록 선정한 대체 서체입니다.

## 2. 컬러

### 2.1 기본 팔레트

| CSS 토큰 | HEX | 사용 위치 |
| --- | --- | --- |
| `--canvas` | `#ECECE8` | 시험지 바깥 화면 바탕 |
| `--paper` | `#FFFFFF` | 시험지, OMR, 성적표의 기본 바탕 |
| `--surface-subtle` | `#F5F5F2` | 성적표 행 제목, OMR 구획 머리글, 버튼 hover |
| `--ink` | `#111111` | 본문, 제목, 선택된 OMR 마킹 |
| `--ink-muted` | `#595954` | 배점, 보조 설명, 페이지 정보 |
| `--rule` | `#222222` | 헤더, 중앙선, 지문·코드 상자, 성적표 구획선 |
| `--rule-soft` | `#D8D8D2` | 종이 외곽선, 정보 구분용 보조선 |
| `--omr-green` | `#2F7057` | OMR 제목, 주요 구획선, 문항 번호 |
| `--omr-rose` | `#9B3D69` | 미선택 OMR 답란의 타원과 숫자 |
| `--incorrect` | `#8C2F2F` | 결과 화면의 `오답` 글자와 표시 |

기본 종이는 순백색으로 고정합니다. 종이의 인상은 바깥 회색 바탕과 활자·여백으로 만듭니다. 노란 빈티지 색, 종이 노이즈 텍스처, 그림자, 그라디언트는 사용하지 않습니다.

### 2.2 OMR 원본색과 화면색

국어 OMR PDF를 Poppler로 긴 변 1000px의 RGB 이미지로 렌더링했을 때 반복되는 녹색은 `#40BC85`, 분홍색은 `#EC008C`였습니다. 이는 해당 렌더링의 픽셀값이며 공식 인쇄색이나 모든 기기에서 동일한 색을 의미하지 않습니다.

웹에서는 원본의 색상 역할을 유지하면서 녹색을 `#2F7057`, 분홍색을 `#9B3D69`로 짙게 조정합니다. 선택 상태는 원본의 검은 사인펜 마킹처럼 `#111111`로 채웁니다. 녹색을 서비스 전체의 브랜드색이나 정답 색으로 확장하지 않습니다.

### 2.3 대비와 상태

흰 바탕에 대한 sRGB 상대 휘도 계산 결과입니다. 일반 텍스트의 기준은 [WCAG 2.2의 최소 대비 4.5:1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 사용합니다.

| 전경 / 배경 | 계산한 대비 | 용도 |
| --- | --- | --- |
| `#111111` / `#FFFFFF` | 18.88:1 | 본문·제목 |
| `#595954` / `#FFFFFF` | 7.04:1 | 보조 설명 |
| `#2F7057` / `#FFFFFF` | 5.87:1 | OMR 문자 |
| `#9B3D69` / `#FFFFFF` | 6.43:1 | OMR 답란 숫자 |
| `#8C2F2F` / `#FFFFFF` | 8.19:1 | 오답 표시 |

`--rule-soft`는 장식적 구분에만 사용하고 입력 경계나 포커스 표시에는 사용하지 않습니다. 선택은 검은 채움, 오답은 `오답` 문구를 함께 사용하여 색상만으로 상태를 구분하지 않습니다.

## 3. 폰트와 타이포그래피

### 3.1 서체 역할

| 역할 | 서체 | 사용할 굵기 |
| --- | --- | --- |
| 문제 지문·선택지·교시·성적표 본문 | `Nanum Myeongjo` | 400, 700 |
| 시험명·영역 제목·표 제목·OMR 조작 | `Noto Sans KR` | 400, 500, 700, 800 |
| 코드 | 시스템 고정폭 글꼴 | 400 |

```css
--font-exam: "Nanum Myeongjo", "Batang", "바탕", serif;
--font-label: "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif;
--font-code: ui-monospace, "SFMono-Regular", Menlo, Consolas, monospace;
```

나눔명조의 500·600 굵기를 가정하지 않습니다. 지문 강조에는 실제 제공되는 700을 사용합니다. 코드에는 추가 웹폰트를 설치하지 않고 시스템 고정폭 글꼴을 사용합니다.

글꼴 파일을 배포할 때는 각각의 [나눔명조 OFL](https://raw.githubusercontent.com/google/fonts/main/ofl/nanummyeongjo/OFL.txt)과 [Noto Sans KR OFL](https://raw.githubusercontent.com/google/fonts/main/ofl/notosanskr/OFL.txt)을 함께 보관합니다. 로딩 방식은 구현 시 정하되 `font-display: swap`을 적용하고, 폰트 로드 뒤 줄바꿈을 다시 확인합니다. 화면에 `font-family`를 선언하는 것만으로 폰트가 설치되거나 로드되지는 않습니다.

### 3.2 스타일 표

크기는 기본 글꼴 크기 16px에서의 CSS px 기준입니다. 구현에서는 글자 크기를 rem으로 옮겨 사용자 확대를 허용합니다. 행간은 배수입니다.

| 스타일 | 서체 / 굵기 | PC 크기 | 모바일 크기 | 행간 | 자간 |
| --- | --- | --- | --- | --- | --- |
| 연도 포함 시험명 | Noto Sans KR / 500 | 20px | 15px | 1.5 | `0` |
| `프론트엔드 영역` | Noto Sans KR / 800 | 40px | 28px | 1.25 | `-0.035em` |
| `제 1교시` | Nanum Myeongjo / 700 | 18px | 15px | 1.4 | `0.02em` |
| 문제 번호 | Nanum Myeongjo / 700 | 18px | 18px | 1.8 | `0` |
| 문제 질문 | Nanum Myeongjo / 700 | 16px | 17px | 1.8 | `0` |
| 지문 | Nanum Myeongjo / 400 | 16px | 17px | 1.8 | `0` |
| 선택지 | Nanum Myeongjo / 400 | 16px | 17px | 1.85 | `0` |
| 배점·주석 | Noto Sans KR / 400 | 13px | 13px | 1.5 | `0` |
| 코드 | 시스템 고정폭 / 400 | 13px | 14px | 1.7 | `0` |
| OMR 제목 | Noto Sans KR / 700 | 18px | 18px | 1.4 | `0.04em` |
| OMR 번호·버튼 | Noto Sans KR / 500 | 14px | 14px | 1.5 | `0` |
| 성적표 제목 | Noto Sans KR / 700 | 26px | 22px | 1.4 | `0.03em` |
| 성적표 항목명 | Noto Sans KR / 700 | 14px | 14px | 1.5 | `0` |
| 성적표 값 | Nanum Myeongjo / 400 | 17px | 16px | 1.6 | `0` |

본문은 왼쪽 정렬하며 한국어 단어 단위 줄바꿈을 기본으로 합니다. 원본의 양끝 정렬을 작은 웹 지면에 그대로 적용해 단어 사이가 과하게 벌어지는 것을 피합니다. 긴 URL·식별자는 별도로 줄바꿈하고, 코드에는 본문 줄바꿈 규칙을 적용하지 않습니다.

## 4. 시험지 지면과 반응형

### 4.1 PC 기준 치수

| 요소 | 값 |
| --- | --- |
| 시험지 1면 기준 | `840 × 1188px`, A4와 동일한 `210:297` 비율 |
| 시험지 외곽 | 1px `--rule-soft`, 모서리 0, 그림자 없음 |
| 시험지 안쪽 여백 | 상하 48px / 좌우 48px |
| 헤더 아래 여백 | 24px |
| 헤더 가로선 | 2px `--rule` |
| 2단 간격 | 32px, 간격 중앙에 1px `--rule` |
| 문항 사이 간격 | 32px |
| 질문 → 지문·코드 | 12px |
| 지문·코드 → 선택지 | 12px |
| 지문·코드 상자 안쪽 여백 | 16px |
| 시험지 ↔ OMR 간격 | 24px |
| OMR 폭 | 288px |
| 전체 콘텐츠 폭 | 최대 1152px, 화면 좌우 여백 최소 24px |
| 화면 상하 여백 | 32px |

시험지 폭 840px는 테두리와 패딩을 포함합니다. 2단의 실제 본문 폭은 각각 약 355px입니다. 전체 레이아웃도 `box-sizing: border-box`를 기준으로 계산합니다.

문제지 헤더는 첫 줄의 시험명을 중앙에 두고, 다음 줄 중앙에 영역 제목, 왼쪽에 교시를 둡니다. 교시 때문에 제목 중심이 밀리지 않도록 독립 배치합니다. 좁은 화면에서는 교시를 별도 줄로 내려 겹침을 막습니다.

시작 화면은 종이 문서의 기재란처럼 가는 구획선으로 성명(필수)·소속(선택) 입력과 시행일·수험번호 자동 발급값을 배열합니다. 번호는 한국 시간 시행일 `YYYYMMDD`와 임의의 6자리 숫자를 조합합니다. 생년월일·성별 등 실제 성적통지표의 민감한 항목은 이 모의 서비스에서 받지 않습니다. 입력 정보는 이번 응시의 문제지·OMR·성적통지표에 표시하며 서버에 저장하지 않습니다.

```text
               2026학년도 프론트엔드 개발자 모의평가
    (제 1교시)            프론트엔드 영역
    ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    1. 다음 코드의 ...          │  3. 다음 설명 중 ...
    ┌────────────────────┐    │
    │ 코드 또는 보기       │    │  ① ...
    └────────────────────┘    │  ② ...
    ① ...                     │  ...
    ...                       │
    2. ...                    │  4. ...
```

이 배치는 구조를 설명하는 예시이며 실제 문항 수를 정하지 않습니다. 각 지면은 왼쪽 단을 먼저 읽고 오른쪽 단을 읽습니다. DOM 순서와 화면 순서를 동일하게 유지하고, 문항을 단 사이에서 잘라 배치하지 않습니다.

### 4.2 화면 폭별 전환

| 화면 폭 | 문제지 | OMR |
| --- | --- | --- |
| 1200px 이상 | 840px 기준 A4 지면, 2단 | 오른쪽 288px 고정 영역 |
| 768~1199px | 최대 840px, 가용 폭에 맞춘 2단, 좌우 안쪽 여백 32px | 하단 Drawer |
| 767px 이하 | 1단 읽기 흐름, 좌우 안쪽 여백 20px, 종이 외곽선 제거 | 하단 Drawer |

1200px은 시험지 840px + OMR 288px + 사이 간격 24px + 화면 양쪽 여백 48px이 들어가는 기준입니다. 좁은 PC 창에서도 같은 조건으로 Drawer로 전환합니다.

PC 기본 지면은 A4 비율로 디자인하고 여러 지면을 세로로 이어 읽도록 합니다. 문항이 넘치면 다음 지면으로 넘기며, 자동 분할의 구현 방식은 개발 단계에서 정합니다. 모바일·글자 확대 상태에서는 고정 높이를 풀고 자연스럽게 늘립니다. `overflow: hidden`이나 전체 화면 축소로 내용을 잘라내거나 글자를 줄이지 않습니다.

## 5. 문항과 코드 스타일

- 문제 번호는 `1.`처럼 표시하고 질문 시작선에 맞춥니다. 배점은 질문 끝 또는 문항 오른쪽에 `[3점]`과 같은 형식으로 둡니다. 실제 배점은 출제 정책에 따릅니다.
- 본문에는 명조를 사용하고, 강조는 700 굵기나 밑줄로 제한합니다. 카테고리 배지와 문항별 색상은 두지 않습니다.
- 객관식 선택지는 `①`부터 `⑤`까지 세로 배열을 기본으로 합니다. 번호 너비 24px를 확보하고 두 번째 줄부터 내용 시작선에 맞춰 들여씁니다. 중복 선택은 선택된 기호를 각각 강조합니다.
- 선택지 사이 여백은 4px입니다. 모바일에서 직접 누르는 답안 영역의 최소 높이는 44px로 유지합니다.
- 단답 입력은 기존 종이·검은 구획선·고정폭 글꼴을 사용합니다. 선긋기는 좌우 항목을 두 열에 놓고 왼쪽을 누른 뒤 오른쪽을 눌러 연결합니다. 연결선은 `--ink` 한 색으로 표시하고, 모바일에서도 드래그를 요구하지 않습니다.
- 코드는 흰 바탕, 1px `--rule` 테두리, 모서리 0, 16px 패딩을 사용합니다. 다크 테마 코드창, 창 제어점, 언어 배지는 두지 않습니다.
- 코드 텍스트는 `--ink` 한 색으로 표시합니다. 들여쓰기와 줄바꿈을 보존하고 코드 영역 안에서만 가로 스크롤을 허용합니다. 코드 글자를 줄여 폭에 맞추지 않습니다.
- 코드 합자 기능은 끄고 `=>`, `===`, `!==` 등 실제 문자를 그대로 구별할 수 있게 합니다.

## 6. OMR 디자인

### 6.1 답안 표

OMR은 별도의 답안 용지처럼 보이도록 흰 바탕과 녹색 테두리를 사용합니다. 제목은 `OMR 답안지`, 표의 머리글은 `문항`과 `답란`으로 구성합니다. 카테고리, 정오답, 성적 정보는 시험 중 표시하지 않습니다.

| 요소 | 값 |
| --- | --- |
| 바깥 테두리 | 1px `--omr-green`, 모서리 0 |
| 안쪽 여백 | 12px |
| 문항 행 | 높이 최소 44px |
| 행 구성 | 번호 28px + 답란 44px × 5, 열 간격 2px |
| 답란 실제 터치 영역 | 44 × 44px 이상 |
| 답란의 시각적 타원 | 가로 18px × 세로 26px, 테두리 1px |
| 미선택 | 흰 바탕, `--omr-rose` 외곽선·숫자 |
| 선택 | `--ink` 채움·외곽선, 흰 숫자 |
| hover | 터치 영역 바탕만 `--surface-subtle` |
| 포커스 | 터치 영역 안쪽에 2px `--ink` 외곽선, 선택 상태와 별도로 유지 |

객관식 OMR 답란은 타원 테두리 안에 `1`~`5`를 넣어 표현합니다. 단일·중복 모두 문제지의 선택 상태와 동기화합니다. 단답·선긋기 행은 기입 여부와 `문제지로` 이동 버튼을 표시하며, OMR에서 텍스트나 연결선을 입력하지 않습니다. 접근 가능한 이름에는 `3번 문항, 2번 선택지`처럼 문항과 답안을 함께 포함합니다.

OMR 상단에는 응시 중인 성명·수험번호를 작은 글씨로 표시합니다. 실제 답안지의 생년월일·성별 기입란, 광학 인식용 검은 눈금, 감독관 확인란, 견본 워터마크, 기관 로고는 넣지 않습니다.

### 6.2 고정 영역과 Drawer

- PC: 스크롤 중에도 보이는 `sticky` 배치, 상단 간격 24px. 높이는 `calc(100dvh - 48px)` 이내로 제한하고 OMR 내부 목록을 스크롤합니다.
- 모바일·좁은 창: 하단에 높이 56px의 `OMR 답안지 열기` 바를 고정합니다. 바탕은 흰색, 위쪽 경계는 1px `--rule`, 하단 안전 영역만큼 패딩을 추가합니다.
- 문제지 끝에도 하단 바 높이 + 안전 영역 + 16px의 여백을 확보하여 마지막 선택지가 가려지지 않게 합니다.
- Drawer: 화면 아래에서 열리고 최대 높이 `70dvh`, 흰 바탕, 위쪽 경계 1px, 모서리 0, 그림자 없음. 넓은 창에서는 내부 답안 표를 최대 288px로 중앙 정렬합니다.
- 359px 이하의 좁은 화면에서는 Drawer 좌우 여백을 8px로 줄여 ①~⑤ 답란의 44px 클릭 폭을 유지합니다.
- 배경 덮개: `rgb(17 17 17 / 32%)`. Drawer 헤더에는 제목과 최소 44px의 닫기 버튼을 둡니다. 드래그 동작만으로 닫도록 만들지 않습니다.
- 열기·닫기는 160ms `ease-out` 이동으로 제한합니다. `prefers-reduced-motion: reduce`에서는 이동 효과를 제거합니다.
- 열린 동안 포커스와 스크롤은 Drawer 안에서 관리하고, Escape 또는 닫기 버튼으로 닫으면 열기 버튼으로 포커스를 돌려줍니다. 선택한 답안과 읽던 위치는 유지합니다.

## 7. 성적표 디자인

성적표는 최대 폭 840px의 흰 문서로 구성합니다. 제목은 `2026학년도 프론트엔드 개발자 모의평가 성적통지표`이며, 긴 제목은 모바일에서 의미 단위로 줄바꿈합니다.

참고한 Q&A 페이지의 주황색 제목 띠는 안내 책자의 편집 스타일이므로 적용하지 않습니다. 성적통지표 예시 안의 흑백 표 구조를 기준으로 합니다.

### 7.1 정보 순서

1. 성적통지표 제목
2. 성명·수험번호·시행일·선택 입력한 소속
3. 총점(36px 명조 굵게)·정답 수·미응답 수
4. 결과 공유·GitHub Star 버튼과 공유 상태 안내
5. 영역별 점수·백분위·등급 표
6. 취약 영역과 응답 문항 기준 정답률·오답 수
7. 전체 해답지: 문항별 펼침, 선택지·제출 답안·정답·해설·근거 링크

| 구분 | JavaScript | TypeScript | React | Browser | CSS | Web Performance |
| --- | --- | --- | --- | --- | --- | --- |
| 점수 | 취득 / 만점 | 취득 / 만점 | 취득 / 만점 | 취득 / 만점 | 취득 / 만점 | 취득 / 만점 |
| 백분위 | — | — | — | — | — | — |
| 등급 | — | — | — | — | — | — |

위 표는 배치 예시입니다. `—`는 미산출 상태이며 표 아래에 사유를 설명합니다. 백분위·등급이 영역별이 아닌 시험 전체 지표로 결정되면, 해당 행은 영역마다 반복하지 않고 `전체 성적` 행으로 구분하여 표시합니다. 디자인 예시로 산정 정책을 확정하지 않습니다.

### 7.2 표와 오답 표시

- 표 바깥선은 2px, 셀 구획은 1px `--rule`, `border-collapse: collapse`를 사용합니다.
- 항목명 셀에만 `--surface-subtle` 바탕을 사용하고 수치 셀은 흰색을 유지합니다.
- 셀 패딩은 세로 12px / 가로 8px, 값은 가운데 정렬합니다. 영역명은 2줄까지 자연스럽게 줄바꿈합니다.
- 모바일에서는 표의 구조를 유지한 채 표 영역만 가로 스크롤합니다. 첫 항목명 열은 고정하고 `좌우로 이동해 영역별 성적을 확인하세요` 안내를 제공합니다.
- 취약 영역은 `취약 영역: …` 문장과 근거를 제시합니다. 막대 차트, 원형 차트, 색상별 등급 카드는 사용하지 않습니다.
- 오답은 `3번 · 오답 · 제출 ② / 정답 ④`처럼 표현하고, `오답`만 `--incorrect`로 표시합니다. 문항 간에는 가는 선과 24px 여백을 사용합니다.
- 공유와 Star는 기존 다시 응시 버튼과 동일한 흰 배경·1px 테두리·44px 최소 높이를 사용하며 모바일에서 줄바꿈합니다. 근거 링크는 밑줄로 식별하고 새 탭 열기를 접근성 이름에 표시합니다.
- 실제 평가원 기관명·직인은 넣지 않고, 사용자가 제공한 성명과 자동 발급한 수험번호만 표기합니다.

둥근 모양은 교시의 작은 타원과 OMR 답란에만 사용합니다. 기본 토큰의 `--radius: 0`은 종이, 상자, 버튼, Drawer에 적용합니다. 다크 모드·컬러 테마는 이번 디자인 범위에 포함하지 않습니다.

- 위 다섯 문자색과 흰 바탕의 대비를 sRGB 상대 휘도 공식으로 계산했습니다.

### 구현 후 검수할 항목

- [ ] 1440px·1280px에서 2단 문제지와 고정 OMR이 겹치지 않는다.
- [ ] 1200px·1199px 경계에서 OMR 배치가 전환되고 답안 상태가 유지된다.
- [ ] 768px·767px 경계에서 문항 읽기 순서를 유지하며 2단과 1단이 전환된다.
- [ ] 390px·320px에서 지문, 긴 제목, ①②③④⑤, 코드가 잘리지 않는다.

- [ ] Drawer의 포커스 이동, Escape, 닫기, 스크롤, 안전 영역을 확인한다.
- [ ] OMR 선택·포커스·미응답 상태가 색상 이외의 형태로 구분된다.
- [ ] 성적표는 표 구조를 유지하며 미산출 지표를 수치로 오인하게 하지 않는다.
- [ ] 실제 사용한 모든 배경·상태 조합의 대비를 다시 확인한다.

React·Next.js 화면 시안은 시작 안내 후 최소 20문항·100점의 문제지를 무작위로 구성하고, A4 비율 지면에 4문항씩 배치합니다. 브라우저에서 30문항 응시와 29문항 재응시, PC·모바일 OMR 답안 동기화, 100점 기준 채점과 타이머 초기화를 확인했습니다. 실제 출제 문항의 지면 분할, 실기기 폰트 렌더링, 전체 키보드·스크린리더 사용성은 아직 검증하지 않았습니다.
