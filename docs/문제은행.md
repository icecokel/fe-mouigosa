# 문제은행 현황

현재 7개 카테고리, 총 700문항입니다. 기존 40문항을 보존하고 660문항을 추가했습니다. 각 카테고리 JSON의 `questions` 배열에 문항을 저장합니다.

| 카테고리 | 2점 | 3점 | 4점 | 5점 | 합계 |
| --- | --- | --- | --- | --- | --- |
| JavaScript | 25 | 25 | 25 | 25 | 100 |
| TypeScript | 25 | 25 | 25 | 25 | 100 |
| React | 25 | 25 | 25 | 25 | 100 |
| Browser | 25 | 25 | 25 | 25 | 100 |
| CSS | 25 | 25 | 25 | 25 | 100 |
| Web Performance | 25 | 25 | 25 | 25 | 100 |
| Design Pattern | 25 | 25 | 25 | 25 | 100 |

JavaScript는 값 변환·배열·객체·함수·컬렉션·반복자 등을, TypeScript는 타입 추론·유틸리티·제네릭·조건부·매핑 타입 등을 다룹니다. React는 상태·Hook·Context·렌더링·서버 경계를, Browser는 DOM·이벤트·네트워크·저장소·워커를 다룹니다. CSS는 선택자·박스·레이아웃·캐스케이드·반응형을, Web Performance는 측정·전송·캐시·렌더링·병목 개선을 다룹니다. Design Pattern은 생성·구조·행동 패턴과 프론트엔드 적용 시 계약·수명·결합의 문제를 다룹니다.

## 시험 구성

매 시험 시작과 재응시 때 다음 조건을 만족하는 문항을 선별하고 순서를 섞습니다.

- 모든 카테고리를 포함하고 한 시험 안에 같은 ID를 중복 출제하지 않습니다.
- 문항의 원래 배점 2~5점을 유지하며 합계는 정확히 100점입니다.
- 문항 수는 최소 20개이며 배점 조합에 따라 달라집니다.
- 영역별 목표는 `100 / 카테고리 수`입니다. 현재 7개 영역에서는 14·14·14·14·14·15·15점이 최적입니다.
- 15점이 배정되는 영역과 실제 문항은 무작위 선택에 따라 바뀔 수 있습니다.
- 문항 부족으로 이상적인 배분이 불가능하면 가능한 100점 조합 중 균등 목표와의 제곱 오차 합이 가장 작은 것을 선택합니다.
- 모든 영역을 포함한 100점 조합 자체가 없으면 오류를 표시하고, 사전 빌드 검사에서도 차단합니다.

`app/exam.mjs`에서 카테고리별로 가능한 배점 합계를 구하고, 영역들을 조합해 최적 배분을 찾습니다. 무작위 순서로 문항과 동률 후보를 선택하므로 영역 균형을 지키면서 시험 내용이 달라집니다. 모든 가능한 시험 조합을 동일 확률로 추첨하는 방식은 아닙니다.

## 검증 범위

- 구조 검증: 카테고리·고유 ID·배점·5개 선택지·정답 범위·조건부 코드 필드·지문/코드 중복.
- 생성 시 확인: 신규 JavaScript 출력 예측 92문항을 Node.js에서 실행해 정답과 대조했습니다. 신규 TypeScript 타입 분석 94문항은 TypeScript 5.9.3의 `strict: true` 컴파일 검사로 기대 타입과 대조했습니다.
- 출제 회귀 검사: 시드가 다른 1,000회 시험의 100점·최소 문항 수·중복 없음·7개 영역 14~15점 배분·원본 데이터 보존을 검사합니다. 문항이 부족한 영역과 불가능한 조합도 검사합니다.
- 전체 700문항에 해설과 주제별 근거 링크를 넣었으며, 시험 종료 후 정답·오답·미응답 모두에서 확인할 수 있습니다. 해설과 유효한 HTTPS 근거 URL은 필수 필드로 검증합니다. 개념·상황 판단 문항의 정답 근거와 난이도 적절성은 기여 PR에서도 검토합니다.

실행·타입 대조는 이번 문항 작성 과정에서 수행한 검사입니다. 일반 PR 검증에서 문항의 코드 문자열을 실행하지는 않습니다. 문항 코드는 실행 대상이 아닌 표시용 데이터입니다.

```bash
npm run check:questions
npm run check
PAGES_BASE_PATH=/fe-mouigosa npm run build
```
