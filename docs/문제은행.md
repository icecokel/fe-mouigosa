JavaScript는 값 변환·배열·객체·함수·컬렉션·반복자 등을, TypeScript는 타입 추론·유틸리티·제네릭·조건부·매핑 타입 등을 다룹니다. React는 상태·Hook·Context·렌더링·서버 경계를, Browser는 DOM·이벤트·네트워크·저장소·워커를 다룹니다. CSS는 선택자·박스·레이아웃·캐스케이드·반응형을, Web Performance는 측정·전송·캐시·렌더링·병목 개선을 다룹니다. Design Pattern은 생성·구조·행동 패턴과 프론트엔드 적용 시 계약·수명·결합의 문제를 다룹니다.

Next.js는 라우팅·렌더링·서버/클라이언트 경계·캐시 등을, Web Fundamentals는 HTTP·URL·인코딩·인증 흐름 등을 다룹니다. Accessibility & SEO는 접근 가능한 HTML·키보드·ARIA와 검색엔진의 수집·색인을, AI Concepts는 모델·토큰·임베딩·RAG·평가·연동 개념을 다룹니다. Web Security는 웹 공격과 방어를, E2E Testing은 실제 사용자 흐름의 자동 검증을, Design System은 토큰·컴포넌트 API·변형·변경 관리를 다룹니다.

`type`은 풀이 방식(개념 판단·결과 예측·타입 분석·버그 찾기·렌더링 횟수 예측·브라우저 동작), `format`은 답안 형식입니다. 현재 객관식 단일 1,400문항, 객관식 중복·주관식 단답·선긋기 각 1문항입니다. 새 형식도 동일한 무작위 문제은행에 들어가므로 매 시험에 반드시 출제되지는 않습니다.

## 시험 구성

매 시험 시작과 재응시 때 다음 조건을 만족하는 문항을 선별하고 순서를 섞습니다.

- 한 시험 안에 같은 ID를 중복 출제하지 않습니다. 카테고리별 문항 수는 고정하지 않으며 0문항인 카테고리도 허용합니다.
- 문항의 원래 배점 2~5점을 유지하며 합계는 정확히 100점입니다.
- 문항 수는 최소 20개이며 배점 조합에 따라 달라집니다.
- 카테고리 가중치에 따라 문항 후보를 추첨하고, 가능한 조합 중 정확히 100점인 시험을 구성합니다. 가중치가 높을수록 출제 비중이 높아질 가능성이 커지지만 영역별 점수 할당량은 없습니다.
- 최소 20문항·100점 조합 자체가 없으면 오류를 표시하고, 사전 빌드 검사에서도 차단합니다.

| 가중치 | 카테고리 |
| ---: | --- |
| 5 | JavaScript |
| 4 | TypeScript, React, CSS |
| 3 | Browser, Next.js, Web Fundamentals, Web Performance, Accessibility & SEO, Web Security, AI Concepts |
| 2 | Design Pattern, E2E Testing, Design System |

가중치는 출제 로직의 상수에서 관리합니다. 시험마다 선택된 문항과 영역별 합계는 달라질 수 있으며, 모든 가능한 시험 조합이 같은 확률로 선택되는 것은 아닙니다. 성적표는 실제 출제된 영역만 집계합니다.

## 검증 범위

- 구조 검증: 문항별 카테고리·유형·형식, 고유 ID, 배점, 형식별 선택지·정답 구조, 조건부 코드 필드, 지문/코드 중복.
- 생성 시 확인: 신규 JavaScript 출력 예측 92문항을 Node.js에서 실행해 정답과 대조했습니다. 신규 TypeScript 타입 분석 94문항은 TypeScript 5.9.3의 `strict: true` 컴파일 검사로 기대 타입과 대조했습니다.
- 출제 회귀 검사: 시드가 다른 1,000회 시험의 100점·최소 문항 수·중복 없음·가중치 반영·원본 데이터 보존을 검사합니다. 불가능한 조합도 검사합니다.
- 전체 1,403문항에 해설과 주제별 근거 링크를 넣었으며, 시험 종료 후 정답·오답·미응답 모두에서 확인할 수 있습니다. 해설과 유효한 HTTPS 근거 URL은 필수 필드로 검증합니다. 개념·상황 판단 문항의 정답 근거와 난이도 적절성은 기여 PR에서도 검토합니다.

실행·타입 대조는 이번 문항 작성 과정에서 수행한 검사입니다. 일반 PR 검증에서 문항의 코드 문자열을 실행하지는 않습니다. 문항 코드는 실행 대상이 아닌 표시용 데이터입니다.

```bash
npm run check:questions
npm run check
PAGES_BASE_PATH=/fe-mouigosa npm run build
```
