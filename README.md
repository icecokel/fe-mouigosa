# fe-mouigosa

**수능 문제지를 펼쳤는데 과목이 프론트엔드인 모의고사 웹페이지.**

`fe-mouigosa`는 한국의 수능·평가원 모의고사 시험지를 웹으로 옮긴 듯한 경험을 만드는 프로젝트입니다. 문제지에서 직접 답을 작성하고, 시험이 끝나면 한국식 성적표로 결과를 확인합니다.

## 핵심 경험

| 구분 | 내용 |
| --- | --- |
| 문제지 | A4 시험지 비율, 흰색 또는 옅은 종이색, 명조 계열 본문, 2단 문제 배치 |
| 문항 | 문제 번호와 배점, 객관식·단답·선긋기 답안, 코드와 지문 |
| 답안 | 문제지의 보기를 누르면 선택한 번호가 검은 원으로 표시됨 |
| 성적표 | 영역별 점수, 백분위, 등급, 취약 영역, 오답 문항 |

시험지 상단에는 다음 문구를 사용합니다.

```text
2026학년도 프론트엔드 개발자 모의평가
제 1교시
프론트엔드 영역
```

## 출제 범위

JavaScript, TypeScript, React, Browser, CSS, Web Performance, Design Pattern, Next.js, Web Fundamentals, Accessibility & SEO, AI Concepts, Web Security, E2E Testing, Design System의 14개 카테고리를 다룹니다.

각 문항은 `category`(지식 영역), `type`(풀이 방식), `format`(답안 형식)을 필수로 갖습니다. 유형은 개념 판단·결과 예측·타입 분석·버그 찾기·렌더링 횟수 예측·브라우저 동작이며, 형식은 객관식 단일·객관식 중복·주관식 단답·선긋기입니다. 현재 객관식 단일 1,400문항과 다른 세 형식의 예시 문항이 각 1개씩 있습니다. 카테고리와 유형 태그는 시험 중 노출하지 않습니다.

## 디자인 원칙

- 실제 시험지의 여백, 문항 번호, 구분선과 활자 중심으로 화면을 구성합니다.
- SaaS 스타일의 카드, 그림자, 그라디언트는 최대한 배제합니다.
- 코드는 읽기 쉬운 고정폭 글꼴을 사용하되 시험지의 전체 분위기를 유지합니다.
- 결과 화면도 대시보드 대신 표와 문서 중심의 한국식 성적표로 구성합니다.
- 모바일에서는 종이의 인상을 유지하면서 지문과 선택지를 읽고 답할 수 있어야 합니다.

## 현재 상태

React 19·Next.js 16으로 **문제지와 성적표 화면 시안**을 구현했습니다. 문제은행은 카테고리별 JSON 14개, 각 100문항에 기존 형식 예시 3문항을 더한 총 1,403문항입니다. 시작·재응시 때마다 카테고리 가중치를 반영해 중복 없이 최소 20문항을 무작위로 선별하고 순서를 섞습니다. 카테고리마다 반드시 문항이 나올 필요는 없습니다. 문항당 2~5점 배점을 유지하면서 총 100점으로 구성하며, A4 비율 지면에 4문항씩 배치합니다. 모든 형식의 답은 문제지에서 작성합니다. 객관식에서 선택한 보기 번호는 흰 숫자가 들어간 검은 원으로 표시됩니다. 문제지 위에는 남은 시간·기입 수·시험 종료 버튼을 두었습니다. 종료하면 답안이 고정되고 성적표에 총점·출제 영역별 점수·취약 영역과 전체 문항의 해답지가 표시됩니다. 각 해답에는 제출 답안·정답·해설·근거 링크를 제공합니다. 결과 공유는 점수 요약과 응시 링크를 전달하며, 공유 API를 지원하지 않으면 텍스트를 복사합니다. GitHub Star 버튼은 저장소로 연결됩니다. 20분 카운트다운이 `00:00`이 되면 자동 제출하고 성적표로 이동합니다. 백분위·등급은 비교 자료가 없어 `—`로 표시합니다.

첫 화면에서 성명을 입력하고 소속을 선택적으로 적습니다. 수험번호는 한국 시간 시행일과 임의 숫자로 자동 발급되며, 입력한 정보와 함께 문제지·성적통지표에 표시됩니다. 발행한 문제·답안·종료 시각은 브라우저에 저장해 새로고침이나 재방문 후에도 같은 시험을 복원합니다. 20분이 지난 뒤 돌아오면 제출된 성적표를 표시하며, 다시 응시를 누르면 기록을 지우고 수험자 정보 화면으로 돌아갑니다. 서버에는 저장하지 않습니다.

```bash
npm install
npm run dev
```

`http://localhost:3000`에서 확인할 수 있습니다. `npm run build`로 프로덕션 빌드를 검증할 수 있습니다.

## GitHub Pages 배포

Next.js 정적 export를 사용하며 `npm run build` 결과는 `out/`에 생성됩니다. GitHub Pages 프로젝트 사이트의 하위 경로를 로컬에서 확인하려면 `PAGES_BASE_PATH=/fe-mouigosa npm run build`를 실행합니다.

저장소는 [icecokel/fe-mouigosa](https://github.com/icecokel/fe-mouigosa)이며, Pages 배포 소스는 **GitHub Actions**로 설정되어 있습니다. `main`에 푸시하거나 Actions에서 `Deploy to GitHub Pages`를 수동 실행하면 `.github/workflows/deploy-pages.yml`이 Pages에서 제공한 하위 경로로 정적 파일을 배포합니다. 배포 주소는 [icecokel.github.io/fe-mouigosa](https://icecokel.github.io/fe-mouigosa/)입니다.

문제는 `content/questions/<category>.json`의 `questions` 배열에 추가합니다. `npm run check:questions`는 카테고리·문항 스키마·ID 및 동일 지문·코드 중복과 100점 시험 구성 가능 여부를 검증하고 전체 문제은행 데이터를 생성합니다. 개발 서버와 빌드 시작 전에도 자동 실행됩니다. 추가 방법은 [문제 기여 안내](CONTRIBUTING.md)에 정리했습니다.

`npm run check`는 무작위 선별·100점 구성·채점을 포함한 모든 검증을 실행합니다. PR에서는 검증과 정적 빌드가 자동 실행됩니다.

`npm run check:countdown`은 남은 시간 계산과 표시를 확인합니다.

`npm run check:results`는 만점·오답·미응답·취약 영역 계산을 확인합니다.

실제 출제 문항과 배점 체계, 백분위·등급 산정 방식은 [기획서의 미정 사항](docs/기획서.md#9-미정-사항)에 남겨두었습니다.
